## Теория

### Структура тест-кейса

| Поле | Обязательное | Что содержит |
|---|---|---|
| ID кейса | да | Уникальный идентификатор |
| Заголовок | да | Краткое название проверки (без слова «Проверка») |
| Шаги | да | Последовательность действий |
| Ожидаемый результат | да | Как система должна отреагировать |
| Постусловия | нет | Приведение системы в исходное состояние |

### Чек-лист vs Test Suite

- **Чек-лист** — краткий список проверок без подробных шагов.
- **Test Suite** — набор тест-кейсов, объединённых по функциональности.

### Тест-план

Документ, описывающий объём работ по тестированию: объекты, стратегию,
расписание, критерии начала и окончания, ресурсы, риски и способы их
разрешения. Ориентир — ГОСТ Р 56922-2016 (ISO/IEC/IEEE 29119-3:2013).

### Тестовые данные

Данные, используемые для проверки функционала. Бывают валидные,
невалидные, случайные, нагрузочные, дублирующие. Нужны для повышения
качества тестирования и экономии времени.

### Тестовый сценарий vs use case

- **Тестовый сценарий** — проверка более высокого уровня: предусловия,
  входные данные, действия, ожидаемые результаты, постусловия.
- **Use case** — сценарная техника описания взаимодействия пользователя
  с продуктом для достижения конкретной цели.
